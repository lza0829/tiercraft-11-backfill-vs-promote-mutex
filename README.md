# 05-tiercraft（筑层）

筑层 — 数仓分层建设台：贴源入仓 → 明细清洗标准化 → 汇总落表 → 层间行数/键对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流按序落库，**不是** 质检隔离签发。
**也不是** 报表看板 / CRUD 后台 / 电商订单前台 / OA 工单。

## 启动

```bash
docker compose up --build
```

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=..\data
uvicorn app.main:app --reload --port 10500

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://localhost:5500 |
| 接口 | http://localhost:10500 |

## 主链

登记主题域 → 贴源层装载夹具 → 明细层清洗标准化 → 汇总层聚合 → 层间对账报告与各层列表数字同源

## 在途互斥与定点回刷

同一主题域内，三类任务持**可查询的在途锁**（`domain_locks` 表，接口 `GET /api/locks`）互斥：

- 定点回刷在途时，禁止启动贴源到明细、明细到汇总任一类提升；
- 任一提升在途时，禁止启动回刷，也禁止启动另一类提升；
- 冲突由后端直接拒绝（HTTP 409，响应写明对端在途类型与对端任务编号），并落一条
  「互斥失败」任务记录；不依赖前端按钮禁用，绕过界面直接调接口同样被拒。

无可见半态保证：

- 数据变更全程在单个事务内完成，任务失败即整体回滚本趟变更；
- 任务失败后主题域置为「不可用待重跑」（`domains.available=0`），成功重跑后自动恢复；
- 主题域对齐状态由已提交数据实时计算，未对齐不会展示成已对齐。

定点回刷（`POST /api/jobs/backfill`，参数 `domain_id` + `biz_day`）：重跑指定业务日的
明细，再在同一事务内重算该业务日对应的汇总键；回刷本身同样持有在途锁。

任务记录（`layer_jobs`）与在途锁同源落 SQLite，在途态、互斥失败原因、任务结果刷新页面
后仍在；进程重启时残留的在途锁会被回收，对应任务判失败并标记主题域不可用待重跑。
